# Slide Plans Preview

## 01. AI Coding的专利接受度正从“能否申请”转向“如何证明人类创造贡献”

- role: cover

Core message: 全球专利体系已接受AI参与研发，但不会接受没有人类创造贡献证明的专利主张。

Layout structure:
- 顶部 20% 为标题区，使用两行以内的结论式大标题。
- 中部左侧放一条横向演进箭头，分成“能否申请 -> 谁是发明人 -> 如何证明贡献”三段。
- 中部右侧放一个强调卡片，写出“管理层核心命题：从工具使用升级到IP治理”。
- 底部用一条窄页脚放三个关键词标签：人类贡献、技术效果、证据链。

Required visible copy:
- 标题：AI Coding的专利接受度正从“能否申请”转向“如何证明人类创造贡献”
- 主结论短句：AI辅助创新正在被接受，AI独立发明并未被接受。
- 右侧强调句：管理层需要回答的不是要不要用AI，而是如何把人机共创结果稳定沉淀为可授权资产。
- 底部标签：人类贡献 / 技术效果 / 证据链

Visual hierarchy:
- 标题最大，横向演进箭头为第二视觉焦点，右侧结论卡片为第三焦点。
- 页面留白充足，避免堆砌项目符号。

Element types:
- title, conclusion strip, process arrow, callout card, footer tags

Style controls:
- 整体采用管理层汇报风格，浅底色，海军蓝+灰蓝为主色，少量铜金色做强调。
- 字体气质稳健、理性、克制，避免科技炫光感。
- 使用轻阴影卡片和细线箭头，呈现“判断升级”而非“技术炫技”。

Audience-driven presentation controls:
- 面向管理层，强调决策含义和治理升级，不展开法律条文。
- 信息密度低到中，突出一句话判断和框架变化。

## 02. 各国正在形成“三层接受度”格局：接受AI辅助、限制AI署名、严查创造性归属

- role: content

Core message: 全球不是简单分成“支持”与“反对”，而是在形成三层接受度结构，企业需要按法域差异设计申请与举证策略。

Layout structure:
- 顶部为标题和一句导语。
- 中间主体做一个三层阶梯或金字塔结构，自上而下分别是“接受AI辅助”“限制AI署名”“严查创造性归属”。
- 每一层右侧配一个短说明卡。
- 页面右下角放一个小型法域分组框：美国/中国/日本/韩国归入“务实审查”，欧洲归入“审慎审查”。
- 底部用一条总结条写“共同底线：AI不能替代人类承担发明人资格与创造性证明”。

Required visible copy:
- 标题：各国正在形成“三层接受度”格局：接受AI辅助、限制AI署名、严查创造性归属
- 三层标签：接受AI辅助 / 限制AI署名 / 严查创造性归属
- 务实审查组：美国、中国、日本、韩国等
- 审慎审查组：欧洲为代表
- 底部总结：共同底线是承认AI辅助创新，但不承认AI独立承担发明人资格。

Visual hierarchy:
- 三层结构是绝对主视觉，法域分组作为辅助说明。
- 让读者先看到“分层”，再看到“国家示例”，最后看到“共同底线”。

Element types:
- title, intro text, layered pyramid or staircase, side cards, grouping box, footer summary strip

Style controls:
- 延续首页配色，加入更明显的分层色阶：深蓝、中蓝、浅蓝灰。
- 图形应偏战略地图/治理框架感，而非学术图表。
- 国家名称做简洁标签，不做旗帜或装饰图标。

Audience-driven presentation controls:
- 面向管理层，重点是帮助其建立全球判断框架，而不是逐国法规背诵。
- 页面中等信息密度，但必须保持清晰阅读顺序。

## 03. 企业竞争的分水岭不在是否使用AI Coding，而在能否把共创过程沉淀为可授权资产

- role: content

Core message: AI Coding 会快速普及，但专利壁垒不会来自工具使用本身，而来自被组织化、证据化的工程创新能力。

Layout structure:
- 顶部标题区下方，主体采用左右对照布局。
- 左侧是“高价值可专利区”卡片组，列出工程方法、系统架构、质量提升、效率优化、场景化方案五项，可做 2x3 模块布局。
- 右侧是“低稳定性区域”卡片组，列出提示词、通用代码片段、纯业务逻辑三项，视觉上用更浅、更弱的样式表达。
- 页面底部中间放一个横向证据链流程：提示 -> 选择 -> 实验 -> 评审 -> 迭代 -> 资产化。
- 右下角可加一句短结论：谁能留下证据链，谁更可能跨国复制专利成果。

Required visible copy:
- 标题：企业竞争的分水岭不在是否使用AI Coding，而在能否把共创过程沉淀为可授权资产
- 左侧组标题：高价值可专利区
- 右侧组标题：低稳定性区域
- 底部流程标签：提示 / 选择 / 实验 / 评审 / 迭代 / 资产化
- 结论短句：专利竞争力最终取决于证据链，而非代码生成速度。

Visual hierarchy:
- 左右对照是主结构，底部证据链流程承担收口作用。
- 左侧高价值区域要明显强于右侧弱价值区域，形成战略取舍感。

Element types:
- title, dual-column comparison cards, process strip, conclusion callout

Style controls:
- 高价值区用深蓝描边和轻铜金强调；低稳定区用灰蓝或浅灰卡片。
- 保持董事会汇报感，避免过于技术化的流程图风格。
- 卡片文案短、标签化，尽量用名词短语而不是长句。

Audience-driven presentation controls:
- 面向管理层，强调资源配置与壁垒构建。
- 减少技术细枝末节，保留可以驱动资源投放的判断。

## 04. 管理层应把AI Coding纳入公司级专利治理：先建机制，再做重点国家与重点场景布局

- role: summary

Core message: 对管理层最重要的动作不是继续观察，而是立即把AI Coding纳入正式的公司级IP治理框架。

Layout structure:
- 页面采用上主下辅结构。
- 上半部分左侧放一个大标题结论，右侧放“现在就要做”的短句强调卡。
- 下半部分做三列行动框，分别是“识别机制”“留痕机制”“分层布局机制”。
- 每个行动框下保留 2 条极简动作语句。
- 最底部放一个治理协同条，写“研发 + 法务 + 知产 = 共同责任边界”。

Required visible copy:
- 标题：管理层应把AI Coding纳入公司级专利治理：先建机制，再做重点国家与重点场景布局
- 三列标题：识别机制 / 留痕机制 / 分层布局机制
- 右侧强调句：把AI Coding从效率工具采购升级为公司级IP治理议题
- 底部协同条：研发 + 法务 + 知产 = 共同责任边界
- 收尾结论：越早建立规则，越容易把AI研发红利转化为跨国可保护资产。

Visual hierarchy:
- 标题和三列行动框共同构成主体，底部协同条作为落点。
- 三列行动框必须整齐、稳重，像管理动作清单而不是项目说明书。

Element types:
- title, executive callout, three action columns, footer governance strip

Style controls:
- 使用最稳健的一页样式作为总结页，强化董事会/经营会质感。
- 色彩更克制，更多留白，强调秩序感与可执行性。
- 适合做结尾页，也适合作为口头汇报时的行动收束页。

Audience-driven presentation controls:
- 面向管理层，最终目标是推动组织动作，而非补充法律知识。
- 标题结论化，动作模块化，方便会中快速讨论与分工。
